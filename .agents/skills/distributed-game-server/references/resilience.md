# 韧性与恢复

## 故障域

定义哪些对象一起重启：单个玩家、单场对局、单个场景分区、一个 application 或一个 node。监督应隔离故障，持久化恢复应还原业务状态。

## 必测场景

- 变更期间 Actor panic。
- 持久提交前后发生 node 丢失。
- 延迟或重复的远程消息。
- 两端仍在运行的网络分区。
- Registrar 或路由缓存故障。
- 数据库变慢、故障切换或连接池耗尽。
- 网关丢失和重连风暴。
- 分片交接中途被打断。
- 混合版本滚动发布。

## 技术手段

- 为有界 Call 设置 deadline 和取消机制。
- 使用带指数退避和抖动的重试预算。
- 在依赖边界实施熔断和准入控制。
- 对租约、会话和分片所有权使用 fencing token。
- 使用幂等恢复与对账任务。
- 为无关区服、场景和外部依赖设置舱壁隔离。
- 带硬 deadline 的优雅排水，并暴露未完成工作。

## 灾备

按数据类别定义 RPO、RTO、备份频率、恢复演练、跨地区依赖、DNS/发现恢复、密钥恢复，以及恢复流量前运维如何证明一致性。未做过恢复演练的备份不算已验证的恢复能力。

## 避免

- 无限重试循环。
- 节点故障后立刻大规模激活。
- 假定 supervisor 重启会保留内存。
- 没有 fencing 时接受两个所有者写入。
- 用健康进程状态掩盖局部恢复失败。
