# 拓扑与分片

## 从路由键开始

为每个服务选择稳定键：账号 ID、玩家 ID、区服 ID、场景/格子 ID、对局 ID、公会 ID 或赛季/地区。需要顺序变更时，同一键必须路由到同一个权威所有者。

## 常见层次

- 边缘网关终止客户端连接，并按会话/玩家路由。
- 区服服务拥有区服内的玩家和世界协调。
- 场景/战斗服务按场景、格子、房间或对局切分模拟。
- 跨服服务负责全局匹配、公会联邦、排行投影、邮件扇出或共享事件。
- 持久化和配置服务应是独立的故障域和扩缩容域。

## 分片映射

定义分片数、哈希/范围函数、放置所有者、版本、缓存 TTL、迁移状态和旧路由响应。分片迁移必须有交接协议：停止或 fence 旧写入、转移/重载状态、发布新映射并拒绝旧 epoch。

## 热点

区分热键与热节点。可通过拆分读投影、空间切分场景、隔离聊天/在线状态、批量扇出、层级聚合或迁移分片缓解。复制不能单独解决单写者变更热点。

## 跨服工作

- 派生视图和通知优先使用异步事件。
- 限制同步跳数并定义局部失败行为。
- 重试和路由切换时保持稳定操作 ID。
- 避免全局广播；采用 topic、地区、人群或层级扇出。

## 故障场景

规划 registrar 数据陈旧、分区时双所有者、交接中节点丢失、网关路由缓存滞后、目标分片不可用，以及大节点故障后的恢复过载。
