# 安全

## 信任边界

将客户端、公开网关、合作方回调、管理工具、配置来源、服务发现和 node 间网络视为不同信任边界。认证服务身份，并对每个敏感动作做授权。

## 客户端规则

- 服务端拥有价格、奖励、背包、位置、冷却和资格的最终权威。
- 校验消息类型、大小、频率、序号、范围和状态转换。
- 保护登录与恢复 token 不被重放，并绑定到适用范围和过期时间。
- 使用会话 fencing，防止旧连接修改新会话。
- 不暴露内部进程名、堆栈、拓扑或密钥。

## 服务与运维规则

- 使用 TLS 和受保护的集群 cookie/token；轮换时不得提交密钥。
- 对 MCP、管理 RPC、GM 命令和数据库凭据实施最小权限。
- 诊断端点默认只读且限制网络可达范围。
- 货币、背包、封禁、发放、配置和破坏性操作必须有审计记录。
- 从日志和追踪中脱敏凭据、个人数据和玩家数据。

## 滥用与可用性

实施分层限流、有界解码/解压、配额、请求成本控制、连接上限和背压。隔离高成本操作，避免滥用挤占登录或控制流量。

## 审查

威胁建模应覆盖认证绕过、ID 替换、重放、重复奖励、过期会话命令、权限提升、不安全管理端点、密钥泄露、注入、反序列化滥用和拒绝服务。
