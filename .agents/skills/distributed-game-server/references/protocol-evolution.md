# 协议与 Schema 演进

## 滚动兼容

滚动发布期间，旧 node 与新 node 会共存。必须定义每种消息和持久化记录是否支持旧 reader/新 writer 与新 reader/旧 writer 组合。

## 消息规则

- 优先增加带安全默认值的字段。
- 不得复用含义不同的字段。
- 对语义变更做版本化，不仅是 wire 结构变更。
- codec 允许时，未知可选字段应可忽略。
- 启动前注册 EDF 类型，并测试混合版本交换。
- 限制消息大小和嵌套集合长度。

## 持久化规则

使用明确 schema/config 版本、确定性迁移、可恢复批次、检查点、指标和回滚限制。不得在流量高峰读数据时自动重写全部记录。

## 发布顺序

条件允许时：先发布兼容 reader，再发布新格式 writer，迁移数据，切换行为，最后在回滚窗口结束后移除兼容逻辑。

## 测试

为支持版本保留 golden payload、round-trip 测试、未知字段测试、畸形输入 fuzz、混合 node stage 测试、快照/日志恢复测试，以及条件允许时的降级/回滚测试。
