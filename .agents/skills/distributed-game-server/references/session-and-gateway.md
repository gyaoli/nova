# 会话与网关

## 登录流程

1. 在玩法 Actor 外完成账号认证。
2. 为账号/玩家获取或递增会话 epoch。
3. 将连接挂接到新 epoch。
4. 激活或定位玩家所有者。
5. 拒绝携带旧 epoch 的命令和断连通知。

会话 epoch 可防止旧网关连接延迟断开后把新会话错误登出。

## 网关职责

- 在解码昂贵 payload 前完成分帧和长度限制。
- 认证后才路由玩法命令。
- 实施 IP、账号、连接与消息类型四层限流。
- 使用有界出站队列并定义慢客户端策略。
- 保留请求/追踪 ID 和会话 epoch。
- 不拥有持久玩法状态。

## 重连

明确重连窗口、恢复 token 生命周期、最后确认序号、重放上限、状态重同步，以及旧玩家 Actor 或网关节点消失时的行为。不得无限保留出站历史。

## 过载与滥用

- 尽早拒绝未认证洪泛。
- 将控制流量与大体量玩法流量隔离。
- 限制解压和解码集合大小。
- 通过抖动和准入控制抵御登录、重连惊群。
- 不信任客户端时间、位置、价格、奖励、冷却完成或重置序号请求。

## 可观测性

记录认证连接数、分阶段登录延迟、重连成功率、重复登录 fencing、收发队列深度、丢弃/拒绝消息、字节数、协议错误、限流决策和路由失败。
