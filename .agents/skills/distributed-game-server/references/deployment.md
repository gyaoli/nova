# 部署

## 发布契约

记录二进制版本、协议兼容性、配置版本、迁移状态、功能开关和回滚边界。不可逆数据迁移后，回滚二进制可能并不安全。

## 优雅排水

1. 停止新会话、对局或分片分配。
2. 在发现系统中标记实例不可用。
3. 继续完成或交接有界的在途工作。
4. 刷新持久状态、事件、日志和遥测。
5. 在硬 deadline 前停止，并报告未完成工作。

## 灰度

通过 tag 或显式分配路由受控人群。比较错误率、尾延迟、邮箱深度、重启、资源使用、持久化滞后、经济不变量和玩家影响指标。定义自动与人工回滚阈值。

## 配置

激活前校验 config，发布不可变版本，暴露当前生效版本，支持范围化发布，并防止某地区或环境的 config 应用于其他地方。

## 迁移

优先采用 expand-and-contract 变更。迁移必须可恢复、幂等、限速，暴露进度和错误，并测试备份恢复及前向恢复。

## 证据

构建和 unit 测试说明产物正确性；stage 多 node 测试说明 harness 中的协议/生命周期行为；灰度说明有限真实流量下的表现；完整发布健康需要在适当窗口内观察生产证据。
