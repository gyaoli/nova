# 领域边界

## 边界映射

| 上下文 | 负责 | 不负责 |
|---|---|---|
| 身份 | 账号认证、平台绑定、封禁 | 实时连接、玩家背包 |
| 网关 | 连接、协议帧、限流、路由、会话挂接 | 持久玩家状态、玩法规则 |
| 会话 | 唯一在线租约、epoch、重连窗口 | 账号凭据、世界模拟 |
| 玩家 | 玩家范围内成长与命令串行化 | 共享场景模拟、全局排行 |
| 世界/区服 | 区服成员、全局公告、世界协调 | 连接协议解析 |
| 场景 | 空间成员、视野、移动权威 | 经济结算 |
| 战斗 | 确定性对局状态、结果产出 | 最终奖励账本 |
| 匹配 | 队列、组队约束、对局提议 | 战斗模拟、账户余额 |
| 社交 | 好友、公会关系、聊天关系 | 玩家背包 |
| 经济 | 货币/物品账本、发放、消耗、对账 | UI 展示、传输重试策略 |
| 排行 | 派生排序视图、赛季 | 玩家成长权威数据 |
| 配置 | 版本化游戏数据、发布目标 | 可变玩家状态 |

## 规则

- 为每个聚合指定所有者，而不是只指定缓存它的服务。
- 通过包级 helper API 暴露命令和事件；尽量将内部 Actor 消息保持私有。
- 复制数据时必须写清数据源、刷新方式、允许陈旧时长和删除策略。
- 不要用一个全局 Actor 协调无关事务；按一致性键和故障域拆分。
- 除非产品不变量要求权威性，否则分析、排行、搜索和通知应视为投影。

## 边界审查

检查：

- 两个上下文能否并发写同一个不变量？
- 一个上下文故障会不会重启无关玩法？
- 同步 Call 是否跨越了多个限界上下文？
- 事件重放后是否仍能得到正确结果？
- 是否把读模型误当成了事务所有者？
