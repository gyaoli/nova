# 持久化与一致性

## 持久化契约

每个变更都要说明何时算持久成功：数据库提交、追加日志、复制账本、快照加日志或其他明确时点。仅更新内存 Actor 状态不代表持久化。

## 模式

- 每个聚合一个写入者可简化顺序和冲突处理。
- 快照加日志适合回放受限、schema 兼容的恢复。
- Transactional Outbox 原子记录状态变更和事件意图，再异步发布。
- Saga 协调多个本地事务，并定义补偿或对账。
- Read-through/write-through cache 必须有明确数据源和失效/版本规则。

## 幂等

可重试命令携带稳定业务操作 ID。去重记录应包含结果或终态、所有者键，并保留到足以覆盖重试和延迟投递。不得只把临时传输引用作为业务 ID。

## 经济

货币和高价值物品必须满足：

- 服务端权威价格与资格；
- 原子本地账本变更；
- 不可变审计记录；
- 非负和溢出不变量；
- 可重复安全的发放/消耗；
- 跨服务局部流程对账；
- 特权操作归因。

## 恢复

限制回放时长与恢复并发量；验证快照版本、日志连续性、最后已提交操作和下游事件发布。恢复必须幂等且可观测。

## 避免

- 没有原子桥接时，同时写数据库和消息 broker。
- 跨远程 Call 持有 DB 事务。
- 把 cache 成功视为持久提交。
- 不做保留/压缩的无限去重表。
- 对货币、所有权或唯一奖励盲目使用 last-write-wins。
