# 玩法服务

## 场景

按场景实例或空间格子分区。定义移动权威、tick 所有者、相邻订阅、视野半径、边界交接和慢客户端行为。将持久玩家成长与高频空间状态分离。

## 战斗

为每场战斗赋予稳定 ID 和受限生命周期。记录回放和争议分析所需的有序输入或权威事件。奖励结算放在易失模拟之外，并以 battle/result ID 保证重复安全。

## 匹配

用唯一 ticket 管理队列成员。定义队伍原子性、取消竞争行为、地区/延迟约束、扩展规则、提议超时、重复建局防护和交给战斗创建的交接方式。

## 公会与社交

按公会串行化成员与角色变更。将高频在线/聊天从持久公会状态中拆出。邀请、申请、踢出和会长转移必须可过期且幂等。

## 排行

除非排名本身控制事务，否则将排行视为投影。对赛季做版本化，接受延迟事件，从权威数据重建，定义并列规则，并防止旧赛季写入。

## 邮件与奖励

将邮件展示与奖励权益分离。领取操作需要唯一 entitlement ID 和原子领取状态。广播邮件应使用模板/人群，而非同步实体化每个收件人。

## 配置

使用不可变、版本化的配置快照。命令或战斗应知道其适用的配置版本。激活新配置前验证兼容性，并明确回滚语义。
