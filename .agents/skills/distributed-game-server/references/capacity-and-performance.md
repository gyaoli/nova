# 容量与性能

## 容量清单

按服务估算：

- 并发身份数和活跃比例；
- 峰值入站/出站每秒消息；
- handler CPU 时间与墙钟时间分位数；
- 邮箱到达速率与服务速率；
- 单活跃 Actor 状态字节数与总 heap；
- 连接数、文件描述符和带宽；
- 数据库读写、事务延迟与连接池限制；
- 节点丢失后的恢复激活/回放速率。

不得以固定的每秒消息量断言作为证明；应以接近生产的 payload 分布，对代表性 handler 和序列化进行基准测试。

## 排队

邮箱持续增长表示在观察窗口内到达量超过服务能力。只有任务独立且瓶颈不是共享数据库、热键、网络链路、锁或下游配额时，增加 worker 才可能有效。

设置有界队列及满载策略：拒绝、丢弃可选工作、降低精度、重定向或抖动后重试。保护控制消息和停机路径不被大流量淹没。

## 延迟预算

将端到端目标分配给网关、路由、Actor 队列、handler、存储、远程 Call、编码和网络。测量 p50、p95、p99 以及同步跳数带来的尾延迟放大。

## 压测

- 模拟登录突刺、重连风暴、热点场景、热门公会、批量邮件、赛季切换和节点恢复。
- 包含真实的键倾斜和 payload 大小。
- 不只测吞吐，也测正确性和被拒绝的工作。
- 对泄漏、timer 累积、去重保留和压缩进行长稳测试。
- 记录 build tag、拓扑、数据集、硬件和配置，并与结果一同保存。
