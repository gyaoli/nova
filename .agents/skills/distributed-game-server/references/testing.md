# 测试策略

## 测试层级

- Unit：Actor 回调分支、不变量、超时/错误路径和发出的消息。
- Property：经济守恒、非负余额、顺序与幂等。
- Fuzz：协议解码、EDF 兼容类型、管理输入和回放流。
- Stage：多个 Ergo node、发现、断连/重连、重启和混合路由。
- Replay：确定性战斗或命令流与恢复日志。
- Integration：数据库、cache、broker 和外部依赖契约。
- Load：代表性流量、键倾斜、背压和恢复容量。
- Soak：泄漏、timer、队列、去重存储和压缩。
- Chaos/故障注入：node 丢失、延迟、丢包、重复投递和依赖故障。

## 必测变更场景

对可重试状态变更，测试首次投递、完成前重复、完成后重复、超时但最终提交、旧 epoch、乱序命令、Actor 重启、持久化前后 node 丢失和对账。

## 证据措辞

- 编译通过：仅代表 API/类型兼容。
- Unit 测试通过：仅代表已测的本地行为。
- Stage 测试通过：仅代表 harness 中的多 node 行为。
- 压测通过：仅代表所述拓扑、负载和阈值。
- 运行时已验证：必须给出环境、版本、时间窗口和观察到的证据。

## 测试数据

使用确定性随机种子、稳定操作 ID、条件允许时的显式时钟、边界值、畸形 payload 和真实热键分布。fixture 中不得使用生产密钥和个人数据。
